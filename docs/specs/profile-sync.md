# 跨机配置互通与重装恢复（Profile Sync）

状态：已确认设计，待实现
目标机器：家里（home）、办公室（office）
共享介质：坚果云同步目录下的 `DeskBox同步\`

## 1. 目录布局

```
DeskBox同步\
  registry.json              机器清单：标签、显示名、最后在线、程序版本
  profile.json               共享配置（布局/规则/抽屉/外观），带 rev 号
  credentials.vault          口令加密的凭证库（见 §5）
  lock.json                  整理锁（租约 10 分钟，每 2 分钟续）
  machines\
    home\
      settings.json          本机设置（路径逻辑化）
      widget-layout.json
      drawer.json
      rules.json
      profile.json           显示名、指纹校验字段、最后在线
      history\2026-11-21T10-00.json   最近 10 份快照
    office\...
  setup-log.jsonl            首次配置/恢复过程日志（追加）
```

机器档案按**标签**命名，不按指纹命名——重装系统后指纹会变，标签不变。

## 2. 逻辑路径

档案中不得出现绝对路径，统一存逻辑名，运行时按本机解析：

| 逻辑名 | 解析来源 |
| --- | --- |
| `@{Desktop}` | `SHGetFolderPathW(CSIDL_DESKTOPDIRECTORY)` |
| `@{Library}` | 收纳库根（本机设置项） |
| `@{SyncRoot}` | 坚果云同步根（探测：客户端配置 → 注册表 → 候选目录验证） |
| `@{UserProfile}` | `%USERPROFILE%` |
| `@{AppData}` | `%LOCALAPPDATA%\DeskBox` |

解析失败（目录不存在）时回退到默认候选并记日志，绝不阻塞启动。

### 2.1 硬约束（违反即拒收）

重装系统、换机器、换用户名之后必须零手工配置，因此以下四条是硬性约束，不是建议：

1. **备份包内禁止出现绝对路径。** 序列化时任何形如 `C:\`、`D:\`、`%USERPROFILE%\...` 的值都必须先转成逻辑名；导入时若发现绝对路径，直接判为无效档案并拒绝应用（不要"尽力修正"）。
2. **"系统默认"= 当次问系统要的真实路径，不是写死的 `%USERPROFILE%\Desktop`。** 桌面可能被 OneDrive／坚果云重定向到任意盘，必须走 `SHGetKnownFolderPath`；硬编码在重定向机器上一定错。
3. **首次安装不询问任何路径。** 安装后即用系统默认值可运行；用户若要自定义（例如资料库放 D 盘），存成 `角色 = 自定义路径` 的**逻辑名映射**，恢复时若新机器无此路径则回退默认并提示一句，不报错。
4. **桌面不参与跨机同步。** 桌面是临时工作区，只同步收纳库；把桌面当归档区会让同步冲突与整理动作互相踩（冲突副本、`.sync` 目录会被误判为待整理文件）。

### 2.2 重装恢复的验收口径

| 场景 | 期望 |
| --- | --- |
| 全新系统，用户目录同名 | 装包 → 输入恢复口令 → 分类法/学习记录/格子布局全回来，零手工 |
| 用户名不同（如 `panrongbo` → `teacher`） | 逻辑名重新解析，全部生效，无"路径不存在" |
| 桌面被 OneDrive 重定向 | 整理仍指向真实桌面，不落到空目录 |
| 档案里被手工塞了绝对路径 | 拒绝导入并提示"档案包含绝对路径，已拒绝" |

## 3. 机器身份与匹配

指纹 = `MachineGuid` + 用户 SID + 主机名（主机名只记录，不参与目录名）。

首次启动匹配打分：

| 条件 | 分值 |
| --- | --- |
| 主机名相同 | +3 |
| 用户名相同 | +2 |
| `@{SyncRoot}` 路径相同 | +2 |
| 最近在线时间最接近 | +1 |

- 分数 ≥ 5：直接继承该档案，通知「已恢复到 <标签> 的配置」
- 分数 < 5：弹一次二选一（家里 / 办公室），选完继承
- 共享区为空：本机作为第一台，创建档案，角色 home

## 4. 角色与单写者

- `home`：默认允许自动整理
- `office`：默认只读（手动整理可用）
- 只有持有 `lock.json` 的机器能执行搬文件；另一台点整理时提示「另一台机正在整理，已排队」
- 租约 10 分钟，每 2 分钟续；异常退出后租约自然过期

## 5. 凭证库（口令加密）

用户设定一个恢复口令，用于跨机/重装后的凭证恢复。

```
算法：AES-256-GCM
KDF ：PBKDF2-HMAC-SHA256，迭代 600,000，盐 16 字节（每个 vault 一份，随机）
Nonce：12 字节随机，每次写入重新生成
文件：credentials.vault

明文结构（JSON，加密前）
{
  "schema": 1,
  "savedAt": "2026-11-21T10:00:00+08:00",
  "items": {
    "nutstore.user": "...",
    "nutstore.password": "...",
    "ai.apiKey": "..."
  }
}

文件结构
{
  "schema": 1,
  "kdf": "pbkdf2-sha256",
  "iterations": 600000,
  "salt": "<base64>",
  "nonce": "<base64>",
  "ciphertext": "<base64>",
  "tag": "<base64>",
  "hint": "用户自填提示（不加密，可选）"
}
```

规则：
- 口令永不明文落盘，只在内存中派生密钥；写入后立刻清零派生密钥
- 本机可用时优先用 DPAPI 加密的本地副本；vault 仅用于换机/重装
- 口令连续错 5 次后锁定 10 分钟（本机计数）
- 用户可随时「作废 vault」，作废后共享区只留不含凭证的档案

## 6. 首次启动流程（`--first-run-setup`）

```
1. 探测同步根 → 找到 DeskBox同步\？
   否 → 创建，作为第一台（home）
2. 读 registry.json → 本机指纹命中某标签？
   是 → 载入该标签档案，结束
3. 未命中 → 打分匹配 → 继承或二选一
4. 解析逻辑路径 → 写 settings.json
5. 自动填默认：球位置（主屏右下，避开任务栏）、热键（三级备选）、语言、主题
6. 成功/失败都写 setup-log.jsonl；失败回退「本地独立模式」，不阻塞启动
```

## 7. 快照与冲突

- 每次退出写 `history\<时间戳>.json`，保留最近 10 份
- `profile.json` 带 `rev`；合并按 id 逐键（格子按 id、规则按 id）
- 冲突保留 `.conflict-<标签>` 副本，不静默覆盖

## 8. 设置页入口

- 「重新自动配置」：重跑 §6（保留现有凭证）
- 「备份到坚果云 / 从坚果云恢复」：手动兜底
- 「设置/修改恢复口令」「作废凭证库」

## 9. 分期

1. 逻辑路径 + 同步区读写 + 指纹 + 首次自动配置 + 角色（验收：两台机看到同样布局）
2. lock 租约 + rev 合并 + 冲突副本 + 排队提示
3. 凭证库（口令加密）+ 重装恢复 + 安装器拉起 first-run-setup

## 10. 坚果云该同步哪个文件夹（重装/多机必读）

结论：**只同步两个目录，桌面不参与。**

| 同步哪 | 路径 | 里面是什么 | 为什么必须同步 |
| --- | --- | --- | --- |
| ① 档案 | `<同步根>\DeskBox同步\` | `registry.json`、`machines\<label>\profile.json`、`credentials.vault`、`history\` | 重装后靠它认回机器档案、解密坚果云账号与 AI Key |
| ② 资料 | `<同步根>\教学资料库\` | 分类后的工作文件（8 个根目录） | 家里的文件和办公室的文件是同一份 |

不对的用法：

- ❌ 同步整个桌面：桌面是临时工作区，天天变；同步会不断产生 `*冲突副本*`、`.sync` 中间件，被整理引擎误判，两台机同时开着还会互相覆盖。
- ❌ 只同步资料库、不同步 `DeskBox同步\`：重装后虽能找回文件，但分类法、学习记录、账号口令全丢，等于从零开始。
- ❌ 把 `DeskBox同步\` 塞进资料库里：档案会被整理引擎当成工作文件归档，必须放在资料库同级。

### 重装系统后的操作顺序

1. 装坚果云客户端，登录同一账号（139 邮箱那个）。
2. 在客户端里把**同步根目录**指到任意固定位置（例如 `D:\Nutstore`），并勾选上面两个目录：`DeskBox同步`、`教学资料库`。
3. 等它同步完（看目录里出现 `registry.json` 与 `01 数学教学` 等）。
4. 装 DeskBox，首次启动选「从备份恢复」，输入恢复口令。
5. 程序按本机身份挑档案、解出凭证、把逻辑路径解析成本机真实路径——不问你任何路径。

> 判定标准：完成后「诊断与维护 → 备份与恢复 → 跨机与重装」里应显示本机标签（home/office）与"已匹配到档案"。
